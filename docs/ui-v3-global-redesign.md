# 豌豆 AI UI v3 全局重设计基线

状态：设计审计完成，等待全局高保真原型验证。  
范围：首页、项目中心、节点画布、素材库、提示词工具、图片工作台、新闻页以及各类工具页。  
原则：先建立产品级界面系统，再迁移页面；不以局部补丁代替全局设计。

## 1. 当前问题不是单个页面

当前项目同时存在多代视觉语言，并通过大量覆盖规则叠加：

| 区域 | 规模 | 主要风险 |
| --- | ---: | --- |
| `app/ai-node-canvas.html` | 约 21,576 行 | 约 338 个 `!important`、1,090 个直接色值、272 处圆角、237 处阴影 |
| `app/styles.css` | 约 4,346 行 | 多套首页/公共组件样式，约 89 处渐变、85 处阴影 |
| `app/fluid-glass.css` | 约 1,902 行 | 约 556 个 `!important`，覆盖范围过大 |
| `app/image-workbench/customize.css` | 约 2,267 行 | 约 496 个 `!important`，形成独立视觉体系 |
| `app/prompt-mind-map.html` | 约 3,324 行 | 独立颜色、面板和交互规则 |

因此局部修改经常产生三个后果：

1. 新规则被旧覆盖层抵消，或者需要继续增加 `!important`。
2. 同一种按钮、弹窗、下拉框和面板在不同页面表现不同。
3. 视觉效果逐步变成卡片、阴影、渐变和圆角的累积，而不是统一产品语言。

## 2. UI v3 产品方向

定位：**画布优先的 AI 原生创作工作台**。

核心体验：

- 内容、素材和创作结果是视觉主体，应用外壳主动退后。
- 常用动作就近出现，复杂设置渐进展开。
- 节点是内容对象，不是后台管理表单。
- 图片、视频、音频、矢量和提示词在同一工作空间中流转。
- AI 助手融入当前上下文，不以传统独立聊天窗口抢占空间。
- 明暗主题共享同一层级逻辑，不通过简单反色生成。

视觉性格：

- 现代、安静、精准、专业。
- 中性色占主要面积，品牌色只用于关键动作。
- 依靠空间、排版、透明度和内容比例建立层级。
- 少边框、少阴影、少胶囊、少装饰性渐变。
- 动效只解释空间关系和系统状态。

## 3. 全局信息架构

所有页面归入四类统一场景：

### A. 启动与项目

- 首页 `index.html`
- 项目中心 `project-hub.html`
- 更新公告、最近项目、快速创建

统一使用“启动台外壳”：顶部产品栏、主任务区、最近内容和低优先级信息抽屉。

### B. 核心创作工作区

- 节点画布 `ai-node-canvas.html`
- 提示词思维导图 `prompt-mind-map.html`
- 图片工作台 `image-workbench/`

统一使用“创作工作区外壳”：顶部上下文栏、左侧工具轨、中央内容区、右侧检查器、底部生成/命令输入。

### C. 内容与素材管理

- 素材库 `asset-library.html`
- 提示词收藏与历史内容

统一使用“资源浏览器外壳”：紧凑导航、筛选工具栏、内容网格/列表、就地预览检查器。

### D. 单任务工具

- 去水印、4K 放大、PNG 工作流、文案和视频提示词等页面
- 今日简报

统一使用“聚焦工具外壳”：简短说明、单一主任务、渐进高级设置、明确结果区。

## 4. 全局外壳规范

### 顶部栏

- 高度固定且紧凑，不使用大面积渐变。
- 左侧只保留返回、项目名和保存状态。
- 中间放置当前场景需要的视图控制。
- 右侧保留分享、通知、主题和设置。
- 次要功能进入溢出菜单，不横向堆满。

### 左侧导航

- 顶级入口保持稳定，不因页面变化而重新排列。
- 图标与文字仅在需要时展开。
- 创作工具采用窄工具轨，内容管理采用可折叠导航。
- 禁止同时出现多套同级侧边栏。

### 中央内容区

- 画布、素材或生成结果占据最大面积。
- 空状态直接引导第一个创作动作，不使用大卡片套小卡片。
- 内容密度根据窗口自适应，不使用固定宽度堆叠。

### 右侧检查器

- 未选择内容时显示工作区级信息。
- 选择节点或素材后显示对应属性。
- 一级选项直接呈现，二级选项使用 Popover 或折叠区。
- 不再为每个功能单独制作不同形态的“二级页面”。

### 底部命令区

- 提示词、模型、参考素材和生成动作形成一个连续操作区域。
- 模型与参数保持次要视觉等级。
- 一个场景只有一个主生成按钮。

## 5. 颜色职责

| 颜色 | 职责 |
| --- | --- |
| 中性色 | 画布、表面、文字、普通控件，占主要面积 |
| 豌豆绿色 | 品牌识别、主要生成动作、成功结果 |
| 选择蓝色 | 节点选中、连接、键盘焦点、编辑定位 |
| 红色 | 错误和破坏性操作 |
| 黄色 | 警告、等待和额度提醒 |

禁止同一种颜色同时承担品牌、选择、运行和成功四种语义。

## 6. 组件家族

以下组件必须成为全局共享组件，不允许页面自行重新设计：

- App Bar / 顶部栏
- Navigation Rail / 导航工具轨
- Inspector / 属性检查器
- Command Composer / 生成输入区
- Node / 节点
- Contextual Toolbar / 上下文工具栏
- Button / Icon Button
- Input / Textarea / Select / Listbox
- Popover / Menu / Dialog
- Tabs / Segmented Control
- Toast / Inline Alert / Progress
- Media Card / Asset Row / Empty State
- Download Action / Result Actions

每个组件必须定义默认、悬停、选中、焦点、加载、成功、错误和禁用状态。

## 7. 禁止继续使用的旧式模式

- 每个区块都添加描边、阴影和大圆角。
- 大量胶囊按钮并列展示普通选项。
- 为“科技感”叠加绿色渐变、发光、玻璃和背景光斑。
- 图标来自多个体系，线宽与尺寸不一致。
- 页面单独定义品牌绿、选中绿、按钮绿和成功绿。
- 使用提示文字代替正式字段标签。
- 用巨大 Toast 展示长错误堆栈。
- 所有设置一直展开，占据主要创作空间。
- 通过增加新的 `!important` 解决覆盖问题。
- 在正式页面中直接试验未经确认的视觉方向。

## 8. 技术重构边界

视觉迁移必须与业务逻辑解耦：

1. 新建独立的 UI v3 token 文件，分为 primitive、semantic、component 三层。
2. 新建共享外壳和组件样式，不继续扩展 `fluid-glass.css`。
3. 旧页面按阶段挂载新 token，禁止一次性全量替换。
4. 先保留旧类名兼容业务选择器，再逐步移除视觉覆盖层。
5. 每迁移一个区域，都要运行原有功能回归和视觉状态检查。
6. `ui-v2-lab.html` 只视为交互结构实验，不作为最终视觉标准。

## 9. 迁移顺序

### 阶段 1：全局高保真原型

制作一张真实完整工作区，而不是组件陈列页。必须同时包含：

- 应用顶部栏
- 左侧工具轨
- 中央节点画布与媒体结果
- 右侧属性检查器
- 底部 AI 命令输入区
- Popover、下拉菜单、运行和错误状态
- 浅色与深色主题

通过标准：看起来像同一个完整产品，而不是拼装的组件库。

### 阶段 2：全局 token 与应用外壳

先统一字体、颜色、间距、图标、主题、层级、按钮和表单，不改具体业务流程。

### 阶段 3：核心画布

迁移节点、连线、选择态、悬浮工具栏、节点详情、右侧助手和底部生成区。

### 阶段 4：项目与素材

迁移首页、项目中心、素材库和提示词管理。

### 阶段 5：专业工具与内容页

迁移图片工作台、思维导图、新闻和单任务工具页。

### 阶段 6：清理与验证

- 移除已失效覆盖规则。
- 降低 `!important` 数量。
- 对比浅色、深色、100%/125%/150% 缩放和常见窗口尺寸。
- 验证键盘导航、焦点、加载、错误、空状态和长文本。
- 运行全部原有功能回归。

## 10. 每阶段验收门槛

每次设计交付只回答以下问题：

1. 是否符合“画布优先、内容优先”的产品方向？
2. 是否仍有传统后台管理系统的卡片堆叠感？
3. 同级操作是否使用相同组件和视觉状态？
4. 主次关系是否不依赖过多颜色和边框？
5. 浅色与深色是否都是独立完成的设计？
6. 是否保留原有功能、数据和操作路径？

任何一项不通过，都不能继续批量迁移。

## 11. 产品参考原则

- 学习 OpenAI Canvas 的上下文工作和并行空间，不复制品牌外观。
- 学习 Adobe Firefly Boards 的无限画布和多媒体统一工作流。
- 学习 Google Flow 的内容生成优先、素材管理和精确编辑。
- 参考产品只用于结构、层级和交互判断，不直接复刻颜色、图标或品牌元素。
