# 豌豆 AI UI v3 功能保留合同

状态：重构前基线。任何 V3 页面替换正式页面之前，都必须更新并通过本合同。

## 1. 核心原则

UI 重构只允许改变视觉呈现和交互编排，不得顺带删除业务能力、数据字段、存储键、节点连线语义或下载格式。旧界面退场前，新旧版本必须并存验证；不能直接在正式页面上边拆边改。

每个迁移批次必须同时满足：

1. 功能入口数量已核对，旧入口有明确的新位置。
2. 默认状态、加载状态、空状态、成功状态、失败状态和取消状态均可到达。
3. 项目保存、关闭恢复、跨项目切换和本地文件下载不退化。
4. 键盘、鼠标、拖拽、缩放、连线和画布选择不退化。
5. 自动化门禁通过，并完成一次真实桌面客户端人工冒烟。

## 2. 当前功能基线

### 全局页面

- 首页：工具入口、最近项目、主题、API 设置、版本与更新入口。
- 项目中心：新建、打开、重命名、收藏、删除、封面、排序、恢复和大量项目加载。
- 节点画布：创建、选择、多选、拖拽、连线、缩放、自动排列、复制、删除、保存、恢复和切换项目。
- 素材库：素材浏览、排序、拖入画布和持久化。
- 提示词工具：输入、增强、历史/模板、缩放与结果回填。
- 图片工作台：图片载入、编辑、生成、结果预览和下载。
- 独立工具页：关键词反推、提示词优化、PNG 工作流、放大、视频提示词和去水印。

### 节点类型

当前创建入口共 11 类，V3 不得漏项：

| 类型 | 必须保留的关键行为 |
| --- | --- |
| `image` | 上传、预览、替换、缩放、作为参考输入 |
| `generator` | 模型、比例、批量、提示词、参考图、生成、取消、重试、下载 |
| `video` | 模型与参数、参考内容、生成、播放、下载 |
| `audio` | 文本输入、声音、格式、语速、指令、生成、播放、下载 |
| `keyword` | 图片输入、识别、关键词保留与回填 |
| `outpaint` | 扩图方向/尺寸、预览、生成、接缝处理、下载 |
| `png` | 抠图、透明通道预览、重新生成、PNG 下载 |
| `psd` | 图片输入、视觉分析、拆层、重试、PSD 下载与失败说明 |
| `sketch` | 草图参考、创意风格、生成与结果保留 |
| `style` | 风格参考、内容参考、生成与结果保留 |
| `vector` | SVG/AI 输出、透明度、预览和大尺寸下载按钮 |

## 3. 交付门禁

### A. 自动化门禁

运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run-ui-v3-regression.ps1
```

该命令只运行不消耗真实 API 的关键回归。真实 API 检查必须显式使用 `-IncludeLiveApi`，避免日常重构误扣额度。

### B. 页面对照门禁

每次迁移提交必须附带同一尺寸下的新旧截图，至少覆盖：

- 1440 × 900 桌面宽屏；
- 1100 × 760 紧凑窗口；
- 选中节点并展开二级面板；
- 空画布和复杂画布；
- 下拉菜单、弹窗、错误提示和下载结果。

### C. 人工桌面冒烟

发布前必须从桌面客户端完成一条真实闭环：打开项目 → 创建节点 → 输入/连接内容 → 生成或模拟结果 → 保存 → 关闭 → 重开恢复 → 下载文件。

## 4. 变更纪律

- 先新增 V3 token 和组件，不覆盖旧业务选择器。
- 业务事件、存储键和序列化结构默认不改名。
- 每次只迁移一个页面族；测试失败时不继续扩大范围。
- 旧页面只有在新页面通过全部门禁后才能删除。
- 新发现的漏项必须先补入本合同和测试，再修复实现。

## 5. 当前已知风险

- `ai-node-canvas.html` 同时承载结构、样式和大量业务逻辑，视觉改动容易误伤事件绑定。
- 多个测试依赖具体 CSS 或文案；迁移时应将其升级为稳定的 `data-testid`/状态契约，而不是简单删掉测试。
- 真实 API、Photoshop/Adobe 集成和下载文件完整性不能只靠静态测试，需要单独的集成验证环境。
- 现有 80 个测试并不等于覆盖 80 项完整功能；本合同是缺失的功能总账，后续发现能力时继续补充。
